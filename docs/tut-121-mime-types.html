Tutorial 121: MIME types

A MIME type names the kind of a piece of data — text/html, image/png, application/json. A server sends it so that the browser knows what to do with the bytes, and a client sends a list of types it understands. This lesson maps file names to types, reads a Content-Type header, and chooses what to send for an Accept header.

What you will learn#

  • what a MIME type (media type, content type) is,
  • mapping file extensions to types (FileExtensionContentTypeProvider),
  • adding a type of your own,
  • reading Content-Type (type, subtype, charset),
  • the Accept header, quality values and wildcards,
  • content negotiation and the answer 406 Not Acceptable.

Tutorial 9 and tutorial 84 used HTTP from the client side and tutorial 55 from the server side. Whenever a body is sent, a type must say what it is.

Note

The content type classes (Microsoft.AspNetCore.StaticFiles, Microsoft.Net.Http.Headers) are part of the ASP.NET Core runtime, so the program has "RingDotNet.Web" in its using { } (Getting started).

The program#

docs/tutorials/t121_mime_types.ring
# Tutorial 121: MIME types - file extensions to content types, reading a Content-Type header, and choosing what to send for an Accept header
load "dotnet.ring"
using {
	"System"
	"System.Net.Mime"
	"RingDotNet.Web"                  # the content type classes of ASP.NET Core are part of its runtime: this line starts it
}

cHeaders = "Microsoft.Net.Http.Headers."

func main
	# A MIME type (media type, content type) names the KIND of a piece of data: text/html, image/png, application/json. A server sends it in
	# the Content-Type header so that the browser knows what to do with the bytes, and a client sends Accept to say what it understands.

	# 1. From a file name to a type. The provider knows the common extensions.
	oProvider = dnNew("Microsoft.AspNetCore.StaticFiles.FileExtensionContentTypeProvider",[])
	? "1. file name -> content type:"
	for cFile in ["index.html","logo.png","photo.JPG","data.json","report.pdf","archive.zip","notes.txt","song.mp3","movie.mp4","style.css","app.js","unknown.xyz123"]
		? "   " + padRight(cFile,16) + contentTypeOf(oProvider,cFile)
	next

	# 2. The mapping can be extended: a type of your own for your own extension
	oProvider.getProp("Mappings").callMethod("Add",[".ring","text/x-ring"])
	? nl + "2. after adding .ring: " + contentTypeOf(oProvider,"program.ring")
	? "   (a file with an unknown type is sent as application/octet-stream: 'some bytes, download them')"

	# 3. Reading a Content-Type header: the type, the subtype and the parameters (the charset says how text is encoded)
	oContentType = dnNew("ContentType",["text/html; charset=utf-8"])
	? nl + "3. text/html; charset=utf-8  ->  media type: " + oContentType.MediaType + ", charset: " + oContentType.CharSet
	oSplit = dnStatic(cHeaders + "MediaTypeHeaderValue","Parse",["application/json; charset=utf-8; q=0.9"])
	? "   with the headers library: type " + oSplit.getProp("Type").toString() + ", subtype " + oSplit.getProp("SubType").toString() + ", quality " + oSplit.getProp("Quality")

	# 4. The Accept header lists what the client understands, with a QUALITY (q) from 0 to 1 for each: the higher, the better. */* means
	#    "anything"; text/* means "any text type". The default quality is 1.
	cAccept = "text/html, application/json;q=0.9, text/*;q=0.5, */*;q=0.1"
	? nl + "4. the client sends: Accept: " + cAccept
	aClient = parseAccept(cAccept)
	for aItem in aClient
		? "   " + padRight(aItem[1],20) + "quality " + aItem[2]
	next

	# 5. Content negotiation: the server offers some types and sends the one that the client likes best
	? nl + "5. what the server sends:"
	for aOffer in [ ["application/json","text/csv"], ["text/csv","text/plain"], ["image/png"], ["text/html","application/json"] ]
		? "   offers " + padRight(joinList(aOffer),28) + "-> " + negotiate(aClient,aOffer)
	next

	# 6. A client that wants a JSON answer: Accept: application/json only. If the server has no JSON, the right answer is the status
	#    406 Not Acceptable, not a guess.
	aStrict = parseAccept("application/json")
	? nl + "6. Accept: application/json, the server offers text/csv: " + negotiate(aStrict,["text/csv"])

func contentTypeOf oProvider,cFile
	aResult = oProvider.callMethod("TryGetContentType",[cFile])
	if aResult[1]
		return aResult[2]
	ok
	return "application/octet-stream  (not known)"

# the Accept header as a list of [type, quality], the best first (the sort is stable: types with the same quality keep their order)
func parseAccept cAccept
	aItems = []
	for cPart in str2list(substr(cAccept,",",nl))
		oValue = dnStatic(cHeaders + "MediaTypeHeaderValue","Parse",[trim(cPart)])
		nQuality = oValue.getProp("Quality")
		if isObject(nQuality)
			nQuality = 1                                        # no q parameter: quality 1
		ok
		aItems + [ oValue.getProp("MediaType").toString(), nQuality ]
	next
	nCount = len(aItems)
	for i = 1 to nCount - 1
		for j = 1 to nCount - i
			if aItems[j][2] < aItems[j + 1][2]
				aTemp = aItems[j]
				aItems[j] = aItems[j + 1]
				aItems[j + 1] = aTemp
			ok
		next
	next
	return aItems

# does the pattern of the Accept header (text/html, text/*, */*) cover the type?
func covers cPattern,cType
	if cPattern = "*/*" or cPattern = cType
		return True
	ok
	nSlash = substr(cPattern,"/")
	return right(cPattern,2) = "/*" and left(cType,nSlash) = left(cPattern,nSlash)

# the offered type that the client likes best, or 406
func negotiate aClient,aOffers
	for aItem in aClient
		if aItem[2] > 0
			for cOffer in aOffers
				if covers(aItem[1],cOffer)
					return cOffer + "  (matched " + aItem[1] + ", quality " + aItem[2] + ")"
				ok
			next
		ok
	next
	return "406 Not Acceptable"

func joinList aList
	cText = ""
	for item in aList
		if cText != ""
			cText += ", "
		ok
		cText += "" + item
	next
	return cText

func padRight cText,nWidth
	return cText + copy(" ",nWidth - len(cText))

How it works#

Type and subtype#

A MIME type has the form **type/subtype**: the type is the family (text, image, audio, video, application) and the subtype the exact format (html, png, json). After a semicolon come parameters: text/html; charset=utf-8 says that the text is encoded in UTF-8 (tutorial 52 explains encodings). A server that sends the wrong type causes real problems: a browser that receives a script as text/plain does not run it, and one that receives a page as text/plain shows the source.

From a file name#

FileExtensionContentTypeProvider.TryGetContentType(name) answers [ found, type ] (tutorial 81 explains the out value) from the extension of the file name, ignoring case (photo.JPG is image/jpeg). The table is built into the library: it knows the usual web, office, audio and video formats, and the exact text for some extensions changes between versions (for example, JavaScript is text/javascript today and was application/javascript before), so a test must not depend on it. For an extension that is not in the table, the right default is application/octet-stream: some bytes — download them, do not show them. Never guess text/html.

Mappings is a dictionary you can extend: Add(".ring", "text/x-ring") teaches the provider a type of your own. Do this once, at the start of the program.

Warning

The extension is what the name says, not what the content is. A file called photo.jpg can hold anything. For files that users upload, do not trust the type that comes with them: check the first bytes of the file (the magic numbers, tutorial 45) and send downloads with Content-Disposition: attachment and the header X-Content-Type-Options: nosniff.

Reading Content-Type#

System.Net.Mime.ContentType parses a header into MediaType and CharSet; the headers library MediaTypeHeaderValue.Parse gives Type, SubType, Quality and the parameters. Their Type and SubType are small structs (StringSegment) that are turned into text with toString().

Accept and quality#

The client's **Accept header lists the types it understands, separated by commas, each with an optional quality** q from 0 to 1 (1 is the default; higher is better, and 0 means never). */* means anything and text/* any text type. The program parses the header, gives each item its quality, and sorts them best first (a simple, stable sort, so types with the same quality keep their order: the client's order breaks ties).

Content negotiation#

The server offers some types, and the best answer is the offered type that the client likes most: for each type of the Accept list, from best to worst, take the first offer that it covers. In step 5, a client that sends text/html, application/json;q=0.9, text/*;q=0.5, */*;q=0.1 gets application/json when the server offers JSON and CSV, gets text/csv when it offers CSV and plain text (matched by text/*), and gets a PNG only through */*. If nothing fits — a client that accepts only JSON and a server that has only CSV — the correct answer is 406 Not Acceptable, so that the client sees at once that the types do not agree, instead of receiving data it cannot use.

In real programs the negotiation also looks at the language (Accept-Language) and the encoding (Accept-Encoding: gzip, br, tutorial 88), with the same quality rules.

What you learned#

  • type/subtype and parameters such as charset,
  • TryGetContentType, the default application/octet-stream, and your own Mappings,
  • the extension is not the content,
  • the Accept list, quality and wildcards,
  • negotiation and 406 Not Acceptable.
