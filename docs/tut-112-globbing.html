Tutorial 112: File patterns (globbing)

Patterns such as **/*.ring describe sets of files, the way a .gitignore file or a build tool does. This lesson uses the Matcher of .NET with include and exclude rules, finds files in a folder tree, and tests a plain list of paths without a disk.

What you will learn#

  • the glob wildcards *, ** and ?,
  • Matcher: AddInclude and AddExclude,
  • finding files in a folder (GetResultsInFullPath),
  • Match on a list of paths that are not on a disk,
  • the case rule of a matcher,
  • extension methods and dnStatic.

Tutorial 5 listed the files of a folder and tutorial 29 used regular expressions. A glob is simpler than a regular expression and made for paths, so it is the language of file selection: build files, ignore files, backup rules, "which files changed".

Note

Microsoft.Extensions.FileSystemGlobbing is part of the ASP.NET Core runtime, so the program has "RingDotNet.Web" in its using { } (Getting started).

The program#

docs/tutorials/t112_globbing.ring
# Tutorial 112: file patterns (globbing) - "**/*.ring", include and exclude rules, matching a list of paths, and finding files in a folder tree
load "dotnet.ring"
using {
	"System"
	"System.IO"
	"RingDotNet.Web"                  # Microsoft.Extensions.FileSystemGlobbing is part of the ASP.NET Core runtime: this line starts it
}

func main
	# A glob pattern describes a set of files with wildcards, like the patterns in a .gitignore file or a build tool:
	#   *      any characters inside one name           *.ring     a.ring, b.ring
	#   **     any number of folders (also none)         **/*.ring  src/a.ring, src/sub/b.ring, a.ring
	#   ?      one character                             file?.txt  file1.txt, fileA.txt
	cBase = makeTree()
	cExt = "Microsoft.Extensions.FileSystemGlobbing.MatcherExtensions"          # Match and GetResultsInFullPath are extension methods (tutorial 109)

	# 1. A Matcher has include rules and exclude rules. A file is in the result when an include rule matches it and no exclude rule does.
	oMatcher = dnNew("Microsoft.Extensions.FileSystemGlobbing.Matcher",[])
	oMatcher.callMethod("AddInclude",["**/*.ring"])
	? "1. **/*.ring :"
	showFiles(oMatcher,cBase)

	# 2. Exclude: everything under "tests" and every file whose name starts with "old_" is left out
	oMatcher2 = dnNew("Microsoft.Extensions.FileSystemGlobbing.Matcher",[])
	oMatcher2.callMethod("AddInclude",["**/*.ring"])
	oMatcher2.callMethod("AddExclude",["tests/**"])
	oMatcher2.callMethod("AddExclude",["**/old_*"])
	? nl + "2. **/*.ring without tests/** and old_* :"
	showFiles(oMatcher2,cBase)

	# 3. Several include rules at once: the code and the documents
	oMatcher3 = dnNew("Microsoft.Extensions.FileSystemGlobbing.Matcher",[])
	oMatcher3.callMethod("AddInclude",["src/*.ring"])
	oMatcher3.callMethod("AddInclude",["docs/**/*.md"])
	? nl + "3. src/*.ring (one folder only) and docs/**/*.md :"
	showFiles(oMatcher3,cBase)

	# 4. A pattern does not need files on a disk: Match(root, list of paths) tests a list of names, for example the files of an archive
	#    (tutorial 108) or the changed files of a project. The paths use / and are relative to the root.
	aPaths = ["src/main.ring","src/old_main.ring","README.md","docs/guide/intro.md","docs/logo.png"]
	oResult = dnStatic(cExt,"Match",[oMatcher3,".",stringList(aPaths)])
	? nl + "4. which of the names are matched: has matches = " + oResult.getProp("HasMatches")
	for oFile in oResult.getProp("Files").toList()
		? "   " + oFile.getProp("Path")
	next

	# 5. By default a Matcher ignores case (OrdinalIgnoreCase). The constructor takes a StringComparison: with Ordinal, case counts.
	oStrict = dnNew("Microsoft.Extensions.FileSystemGlobbing.Matcher",[ :comparisonType = "Ordinal" ])
	oStrict.callMethod("AddInclude",["**/*.RING"])
	oResultStrict = dnStatic(cExt,"Match",[oStrict,".",stringList(["a.ring","b.RING"])])
	? nl + "5. with Ordinal comparison, **/*.RING matches only: " + oResultStrict.getProp("Files").toList()[1].getProp("Path")

	new Directory().Delete([ :path = cBase, :recursive = True ])

# the files of the program, with their relative paths in sorted order (the order of a disk is not the same on every system)
func showFiles oMatcher,cBase
	oResult = dnStatic("Microsoft.Extensions.FileSystemGlobbing.MatcherExtensions","GetResultsInFullPath",[oMatcher,cBase])
	aNames = []
	for cFull in oResult.toList()
		aNames + substr(substr(cFull,cBase + "\",""),cBase + "/","")
	next
	for cName in sort(aNames)
		? "   " + substr(cName,"\","/")
	next
	? "   (" + len(aNames) + " files)"

func makeTree
	oPath = new Path()
	cBase = oPath.Combine([oPath.GetTempPath(),"ringdotnet_tutorial112"])
	if new Directory().Exists(cBase)
		new Directory().Delete([ :path = cBase, :recursive = True ])
	ok
	for cFile in ["src/main.ring","src/old_main.ring","src/util/tools.ring","tests/test1.ring","docs/readme.md","docs/guide/intro.md","docs/logo.png","build.txt"]
		cFull = oPath.Combine([cBase,substr(cFile,"/",oPath.DirectorySeparatorChar)])
		new Directory().CreateDirectory(oPath.GetDirectoryName(cFull))
		new File().WriteAllText([ :path = cFull, :contents = "x" ])
	next
	return cBase

# the Matcher wants a collection of texts (IEnumerable of string): a List<string>
func stringList aList
	oList = dnNewGeneric("System.Collections.Generic.List",["System.String"],[])
	for cItem in aList
		oList.callMethod("Add",[cItem])
	next
	return oList

How it works#

The wildcards#

PatternMatches
*.ringany file name that ends with .ring, in one folder
?exactly one character: file?.txt is file1.txt and fileA.txt
**any number of folders, also none: **/*.ring is a.ring, src/a.ring and src/util/a.ring
src/*.ringfiles in src, not in its sub-folders
docs/**/*.mdevery .md file below docs, at any depth

The separator is always /, on every system.

Include and exclude#

A Matcher collects include rules (AddInclude) and exclude rules (AddExclude). A file is in the result when at least one include rule matches it and no exclude rule does. In step 2, **/*.ring finds four files, then tests/** removes everything in tests and **/old_* removes every file whose name starts with old_, leaving two. Several include rules are joined (step 3: the code of one folder and all the documents).

Files on a disk#

GetResultsInFullPath(matcher, folder) walks the folder and gives the full paths of the matching files. The order is the order of the file system, which is not the same on every system, so the program sorts the names before printing. GetResultsInFullPath and Match are extension methods of MatcherExtensions, so they are called with dnStatic(type, method, [arguments]) (tutorial 109); AddInclude and AddExclude are real methods of the object. The class is made with dnNew(type, []) because the namespace has no generated Ring classes.

A list of names#

Match(root, files) applies the patterns to a list of paths that need not exist: the names inside an archive (tutorial 108), the files that a version control system reports as changed, the lines of a file. It needs a root (use ".", an empty text is read as a missing value) and a .NET collection of texts: the program makes a List<string> (stringList), because a plain Ring list is not accepted for an IEnumerable<string>. The result has HasMatches and Files, each file with its Path.

Case#

By default a matcher ignores case: *.ring also finds B.RING. The constructor takes a StringComparison; with Ordinal, **/*.RING matches only names written in capitals (step 5). Use Ordinal for file systems that care about case.

What you learned#

  • *, ** and ?, and why ** also matches no folder,
  • include rules and exclude rules,
  • GetResultsInFullPath for folders, Match for lists of names,
  • sorted output for a stable result,
  • the "." root and the List<string> input.

Exercises#

  1. Write findFiles(cFolder, aInclude, aExclude) that returns the relative names as a Ring list.
  2. Read the patterns from a settings file (tutorial 111) and use them for a backup program (tutorial 46).
  3. Make a matcher that finds the images (**/*.png, **/*.jpg) but not those in a folder thumbs.
  4. Test your patterns on a list of names with Match before you run them on the disk.
