Tutorial 8: Hashing and encryption

Checksums that fingerprint data, password hashes that are safe to store, a key that proves a message was not changed, random tokens and real encryption with AES.

What you will learn#

  • the difference between hashing and encryption,
  • SHA-256 hashes,
  • storing passwords correctly with a salt and many rounds (PBKDF2),
  • HMAC and random tokens,
  • encrypting and decrypting text with AES.
Warning

This is a first look at the ideas, not a security course. For real systems use the standard libraries as shown here, never invent your own scheme, and keep keys out of your source code.

Hashing and encryption#

HashingEncryption
Directionone way: you cannot get the data backtwo ways: you can decrypt with the key
Result sizealways the same (SHA-256: 32 bytes)about the size of the data
Usecheck that data is the same; store passwordskeep data secret

A hash is a fingerprint. The same input always gives the same hash; a tiny change gives a completely different hash.

The program#

docs/tutorials/t08_security.ring
# Tutorial 8: hashing and encryption basics - checksums, password hashes, random tokens, AES
load "dotnet.ring"
using {
	"System"
	"System.Security.Cryptography"
	"System.Text"
}

func main
	oConvert = new Convert()

	# A hash is a fingerprint of data: the same input always gives the same hash, you can not go back
	? "SHA-256 of 'abc'   : " + lower(oConvert.ToHexString(new SHA256().HashData("abc")))
	? "MD5 of 'abc'       : " + lower(oConvert.ToHexString(new MD5().HashData("abc"))) + "  (old: do not use it for security)"
	? "Changing one letter: " + left(lower(oConvert.ToHexString(new SHA256().HashData("abd"))),16) + "... is completely different"

	# Never store a password: store a salted slow hash (PBKDF2) of it
	cPassword = "correct horse battery staple"
	oSalt = new RandomNumberGenerator().GetBytes(16)
	cHash = hashPassword(cPassword,oSalt)
	? nl + "Stored hash       : " + left(cHash,32) + "... (" + len(cHash) + " characters)"
	? "Right password    : " + (hashPassword(cPassword,oSalt) = cHash)
	? "Wrong password    : " + (hashPassword("wrong",oSalt) = cHash)

	# HMAC: a hash with a secret key proves that a message was not changed
	oHmac = dnNew("HMACSHA256",[ :key = "secret key" ])
	? nl + "HMAC             : " + left(lower(oConvert.ToHexString(oHmac.ComputeHash("message"))),32) + "..."

	# Random bytes for tokens: use RandomNumberGenerator, not Random
	? "Random token      : " + lower(oConvert.ToHexString(new RandomNumberGenerator().GetBytes(8)))

	# AES: encrypt and decrypt a text with a key
	oAes = new Aes().Create(NULL)
	oAes.GenerateKey()
	oAes.GenerateIV()
	cText = "Ring talks to .NET crypto"
	cCipher = oAes.CreateEncryptor(NULL).TransformFinalBlock(cText,0,len(cText))
	? nl + "Encrypted        : " + len(cCipher) + " bytes (the text had " + len(cText) + ")"
	? "Decrypted        : " + oAes.CreateDecryptor(NULL).TransformFinalBlock(cCipher,0,len(cCipher))

# PBKDF2: many rounds make guessing slow
func hashPassword cPassword, cSalt
	oDerive = dnNew("Rfc2898DeriveBytes",[ :password = cPassword, :salt = cSalt, :iterations = 10000, :hashAlgorithm = new HashAlgorithmName().SHA256 ])
	return lower(new Convert().ToHexString(oDerive.GetBytes(32)))

The random values (the salt, the token) change on every run, so your output will differ in those lines.

How it works#

SHA-256 and MD5#

new SHA256().HashData("abc") returns the hash bytes; Convert.ToHexString writes them as hexadecimal. SHA-256 is the modern standard. MD5 is broken for security: it is only fine for a quick checksum of a download.

Passwords#

Never store a password, and never store a plain hash of it either (attackers have tables of hashes of common passwords). Store a salted, slow hash:

  • a salt is random data mixed in, so two people with the same password get different hashes,
  • many rounds (iterations) make each guess slow for an attacker.

Rfc2898DeriveBytes (PBKDF2) does both. To check a login you hash the typed password with the same salt and compare it with the stored hash. The program shows the right password matching and a wrong one failing. (Store the salt next to the hash.)

HMAC#

An HMAC is a hash that needs a secret key. If you and a server share the key, an HMAC on a message proves the message was not changed on the way.

Random tokens#

For secrets (session ids, reset links) use RandomNumberGenerator.GetBytes(n). The ordinary Random class is predictable and must not be used for secrets.

AES#

AES is the standard encryption. Aes.Create(NULL) makes an encryptor; GenerateKey() and GenerateIV() create a random key and initialisation vector; CreateEncryptor(NULL).TransformFinalBlock(text, 0, length) encrypts, CreateDecryptor(NULL) decrypts. Anyone with the key and the IV can decrypt, so those must be kept safe and passed to the receiver separately from the data.

What you learned#

  • hashing is one way, encryption is two ways,
  • a password hash needs a salt and many rounds,
  • RandomNumberGenerator for secrets,
  • NULL selects a method's version without parameters.

Exercises#

  1. Write checksum(cFile) that returns the SHA-256 of a file's bytes (File.ReadAllBytes).
  2. Make a tiny "user store": a dictionary of user → [salt, hash] with register and login functions.
  3. Compute the HMAC of a message with two different keys. Are the results different?
  4. Encrypt a file's text with AES and write the cipher as Base64 text.
