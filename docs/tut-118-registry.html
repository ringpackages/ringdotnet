Tutorial 118: The Windows Registry

Windows and many programs keep their settings in the Registry, a tree of keys that hold values. This lesson reads and writes values of every common type in HKEY_CURRENT_USER, lists values and sub-keys, and cleans up after itself. It runs on Windows only.

What you will learn#

  • the Registry as a tree of keys with values,
  • HKEY_CURRENT_USER and why it is the safe place to write,
  • CreateSubKey, OpenSubKey, SetValue, GetValue,
  • the value kinds: String, DWord, QWord, MultiString, ExpandString, Binary,
  • listing values and sub-keys, deleting them,
  • the rules for a program that writes to the Registry.

Tutorial 32 saved settings in a file. On Windows, programs often use the Registry for the same job, and a program that works with Windows (file types, start-up, system settings) must.

The program#

docs/tutorials/t118_registry.ring
# Tutorial 118: the Windows Registry - keys and values in HKEY_CURRENT_USER, value types, listing, a settings class, and deleting what you made
# (Windows only: anywhere else the program says so and stops)
load "dotnet.ring"
using {
	"System"
	"Microsoft.Win32"
}

C_PATH = "Software\RingDotNetTutorial118"

func main
	if not iswindows()
		? "The Registry exists only on Windows."
		return
	ok

	# The Registry is a tree of KEYS (like folders) that hold VALUES (a name and data with a type). Windows and many programs keep their
	# settings in it. The part HKEY_CURRENT_USER (HKCU) belongs to the user who is logged in and needs no special rights; the part
	# HKEY_LOCAL_MACHINE is for all users and needs an administrator for writing. This lesson writes only in its own key under HKCU
	# and deletes it at the end.
	oUser = dnType("Microsoft.Win32.Registry").getProp("CurrentUser")
	oUser.callMethod("DeleteSubKeyTree",[C_PATH,False])           # a key from an earlier run goes away (False: no error when it is missing)

	# 1. CreateSubKey makes a key (or opens it when it exists) and gives it ready for writing
	oKey = oUser.callMethod("CreateSubKey",[C_PATH])
	? "1. the key HKEY_CURRENT_USER\" + C_PATH + " was made: " + (not oKey.isNull())

	# 2. SetValue(name, data, kind). The kind says how Windows stores the data: String, DWord (a 32-bit number), QWord (64 bits),
	#    MultiString (a list of texts), ExpandString (a text with %NAME% variables that Windows replaces) and Binary (bytes: see the page,
#    a Binary value needs a real byte[] object, which a Ring program can not hold, so this lesson does not write one).
	oKey.callMethod("SetValue",["UserName","Ann","String"])
	oKey.callMethod("SetValue",["WindowWidth",1280,"DWord"])
	oKey.callMethod("SetValue",["LastFiles",stringArray(["a.txt","b.txt","c.txt"]),"MultiString"])          # MultiString needs a string[]: a List<string> and ToArray()
	oKey.callMethod("SetValue",["DataFolder","%USERPROFILE%\Data","ExpandString"])
	oKey.callMethod("SetValue",["BigNumber",5000000000,"QWord"])          # a number above 2147483647 needs 64 bits
	? nl + "2. values written: " + oKey.getProp("ValueCount")

	# 3. Reading: GetValue(name, default) gives the data in the form that fits its kind, or the default when the name is missing
	? nl + "3. UserName    = " + oKey.callMethod("GetValue",["UserName","(none)"])
	? "   WindowWidth = " + oKey.callMethod("GetValue",["WindowWidth",800]) + "   (a number, so " + (oKey.callMethod("GetValue",["WindowWidth",800]) + 20) + " after + 20)"
	? "   Missing     = " + oKey.callMethod("GetValue",["Missing","(default)"])
	? "   LastFiles   = " + listText(oKey.callMethod("GetValue",["LastFiles"]).toList())
	cFolder = oKey.callMethod("GetValue",["DataFolder"])
	? "   DataFolder  = ends with \Data: " + (right(cFolder,5) = "\Data") + ", still has a % sign: " + (substr(cFolder,"%") > 0) + "   (Windows replaced %USERPROFILE%; the path is not printed because it holds your user name)"
	? "   BigNumber   = " + oKey.callMethod("GetValue",["BigNumber"]) + "   (a 64-bit number)"

	# 4. The kind of a value, and a list of all values. GetValueKind tells how it is stored.
	? nl + "4. all the values with their kinds:"
	aNames = sort(oKey.callMethod("GetValueNames",[]).toList())
	for cName in aNames
		? "   " + padRight(cName,12) + oKey.callMethod("GetValueKind",[cName])
	next

	# 5. Sub-keys: a key can hold other keys, like folders. GetSubKeyNames lists them.
	oChild = oKey.callMethod("CreateSubKey",["Window1"])
	oChild.callMethod("SetValue",["Left",100,"DWord"])
	oChild.callMethod("SetValue",["Top",50,"DWord"])
	oChild.callMethod("Close",[])
	oKey.callMethod("CreateSubKey",["Window2"]).callMethod("Close",[])
	? nl + "5. sub-keys: " + listText(sort(oKey.callMethod("GetSubKeyNames",[]).toList()))
	oRead = oKey.callMethod("OpenSubKey",["Window1"])
	? "   Window1 has Left = " + oRead.callMethod("GetValue",["Left"]) + ", Top = " + oRead.callMethod("GetValue",["Top"])
	oRead.callMethod("Close",[])

	# 6. Delete one value, and the whole tree at the end. Always clean up what a test or a sample wrote.
	oKey.callMethod("DeleteValue",["BigNumber"])
	? nl + "6. after DeleteValue(BigNumber): " + oKey.getProp("ValueCount") + " values"
	oKey.callMethod("Close",[])
	oUser.callMethod("DeleteSubKeyTree",[C_PATH])
	? "   the key was deleted: " + oUser.callMethod("OpenSubKey",[C_PATH]).isNull()

func listText aList
	cText = ""
	for item in aList
		if cText != ""
			cText += ", "
		ok
		cText += "" + item
	next
	return cText

func padRight cText,nWidth
	return cText + copy(" ",nWidth - len(cText))

# a string[] from a Ring list (the registry wants the exact type)
func stringArray aList
	oList = dnNewGeneric("System.Collections.Generic.List",["System.String"],[])
	for cItem in aList
		oList.callMethod("Add",[cItem])
	next
	return oList.callMethod("ToArray",[])

How it works#

Keys and values#

The Registry looks like a file system: keys are the folders, and each key holds values, a name with data and a type. The big branches are hives: HKEY_CURRENT_USER (HKCU) belongs to the user who is logged in, HKEY_LOCAL_MACHINE (HKLM) is for the whole computer, HKEY_CLASSES_ROOT holds the file types. The program writes only in HKCU, under its own key Software\RingDotNetTutorial118, because that needs no administrator rights and does not affect other users. HKLM needs an administrator to write.

Registry.CurrentUser is a static property of the class, read with dnType("Microsoft.Win32.Registry").getProp("CurrentUser"). CreateSubKey(path) makes a key (or opens it when it exists) for writing, OpenSubKey(path) opens an existing one for reading (and answers null when it does not exist), and Close() lets go of it. Paths use the backslash: in a Ring text "Software\RingDotNetTutorial118" is written as it is.

The kinds of value#

SetValue(name, data, kind) writes a value, and the kind says how Windows stores it:

KindDataUse
Stringtextnames, paths
DWorda 32-bit whole numbersizes, flags, counters
QWorda 64-bit whole numberbig numbers (5 000 000 000 does not fit 32 bits)
MultiStringa list of textsa list of recent files
ExpandStringtext with %NAME% variablesa path such as %USERPROFILE%\Data: GetValue gives the text with the variable already replaced
Binarybytespictures, encrypted data

A MultiString needs a real string[], so the program builds one from a List<string> with ToArray() (stringArray). A Binary value needs a real byte[] object; in this package a byte array that comes back from .NET is turned into a Ring text, and a Ring text goes back as a string, so a Ring program cannot hold the object to pass it. This lesson therefore does not write Binary values; store bytes as Base64 text in a String value (tutorial 64).

Reading#

GetValue(name, default) gives the data in the form that fits its kind — a Ring number for DWord and QWord, a text for String, a list (toList()) for MultiString — or the default when the name does not exist. GetValueKind(name) tells the kind, GetValueNames() lists the names and GetSubKeyNames() lists the sub-keys, and ValueCount counts the values. The program sorts the names, because the order of the Registry is not defined. Always give a default: a program that reads a value that is not there yet (the first run, a different version) must still work.

Cleaning up#

DeleteValue(name) removes one value, DeleteSubKeyTree(path) the key with everything inside it. The second argument False means no error when the key is missing, which the program uses to remove a key left by an earlier run. Always clean up what a test or a sample wrote: the Registry has no recycle bin, and old keys stay for ever.

Rules for programs that use the Registry#

  • Write only under HKCU\Software\<your company>\<your program>. Never change keys of other programs or of Windows.
  • Do not store secrets in plain text: any program of the same user can read HKCU. Use the Data Protection API (tutorial 113) or the Windows credential store.
  • Read with a default and handle an invalid value; users and other tools edit the Registry.
  • Do not put data there that is big (a few kilobytes is fine, megabytes are not): use a file (tutorial 5).
  • Prefer a settings file when the program must also run on Linux or macOS, or when you want the user to copy the settings to another computer (tutorial 111).
  • Programs that start with Windows use the key Software\Microsoft\Windows\CurrentVersion\Run: add an entry only when the user asked for it, and remove it when the program is uninstalled.
Warning

Changing the Registry can break programs and sometimes Windows. Use only your own keys, check each path before you delete, and never run code from the internet that edits the Registry.

What you learned#

  • the Registry is a tree of keys and values; HKCU is yours,
  • CreateSubKey, OpenSubKey, SetValue, GetValue, GetValueKind,
  • the value kinds and how they come back in Ring,
  • listing and deleting, and cleaning up,
  • the rules for a program that writes there.
