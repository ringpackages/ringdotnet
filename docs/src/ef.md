## The idea

Ring cannot declare .NET classes, so a Ring program **describes the model with data**: a list of tables, each with a list of columns. EF Core works on that model in two ways:

| Class | Rows are | Best for |
|---|---|---|
| `RingDatabase` | lists of `[name, value]` pairs | scripts, tools, small apps — the simplest API |
| `RingEntityDb` | real .NET objects (classes generated from the schema) with navigation properties | change tracking, `Include`, an object-oriented style |

Both support SQLite (bundled), an in-memory database, and SQL Server, PostgreSQL and MySQL when their EF Core package is available.

```ring
load "dotnet.ring"
using { "RingDotNet.Data" }              # loads Entity Framework Core and the RingDatabase classes
```

## A table and its rows

The schema is a list of tables: `[tableName, [ [column, type, isKey, options], ... ]]`. Column types: `int long double decimal string bool datetime bytes`. An `int` or `long` key is generated by the database.

{{source:docs/examples/ef_basic.ring}}

{{output:docs/examples/ef_basic.ring}}

- `insert` returns the key. `byKey` returns the row, or `""` when it does not exist.
- A row is `[["Id",1],["Name","Ann"],...]`; read a column with `dbValue(aRow,"Name")`.
- `where` takes SQL with `{0}` `{1}` parameters. They are **real SQL parameters**: there is no injection (`"x' OR '1'='1"` is just a string).

> [!NOTE] `datetime` columns are texts like `"2024-03-05 10:30:00"`, `bytes` columns are hex texts (`str2hex` / `hex2str`), `bool` columns are `1` / `0`.

## Column options

The optional fourth item of a column is a list of `[name, value]` options:

| Option | Meaning |
|---|---|
| `["required",1]` | `NOT NULL` for text columns |
| `["nullable",1]` | the column accepts null (a number can then be empty) |
| `["unique",1]` | a unique index — a duplicate raises an error |
| `["index",1]` | a plain index |
| `["maxlength",40]` | maximum length of a text |
| `["default",5]` | default value (numbers or text) |
| `["references","Authors"]` | foreign key to the key of another table |
| `["ondelete","cascade"]` | `cascade`, `restrict`, `setnull`, `noaction` |
| `["convert","upper"]` | a value converter (see [hooks](ef-reference.html#hooks)) |

Several columns with `isKey = 1` make a **composite key**: `byKey("Enrollments",[studentId,courseId])`.

A failed save (a unique violation, a missing required value...) raises an error **and forgets its changes**, so the next call starts clean; the message includes the database's own message.

## Queries as data

For anything beyond a SQL condition, describe the query as data. EF Core builds a real **LINQ expression tree** from it and translates it to SQL, so it works with every provider:

{{source:docs/examples/ef_queries.ring}}

{{output:docs/examples/ef_queries.ring}}

Conditions are `[column, op, value]` with `op` one of `=  !=  <  <=  >  >=  contains  startswith  endswith  in  isnull  notnull`, combined with `["and", c1, c2]`, `["or", c1, c2]` and `["not", c]`. `sqlRows` runs any SELECT and returns rows of any shape — joins, groups, computed columns.

## Transactions and manual saving

```ring
oDb.begin()
oDb.update("Accounts",nA,[["Balance",70]])
oDb.update("Accounts",nB,[["Balance",80]])
oDb.commit()                         # or oDb.rollback()

oDb.autoSave(false)                  # changes are written together by save()
oDb.insert("Accounts",[["Owner","D"],["Balance",5]])
oDb.insert("Accounts",[["Owner","E"],["Balance",6]])
oDb.save()
oDb.autoSave(true)
```

The async versions return a .NET `Task`; `dbWait` waits for it and returns the result:

```ring
oTask = oDb.insertAsync("Accounts",[["Owner","F"],["Balance",7]])
? dbWait(oTask)                      # the key
? len(dbWait(oDb.allAsync("Accounts")))
```

## Migrations

`migrate()` brings an **existing** database in line with the model: it creates the missing tables, columns and indexes and returns the list of changes. `apply(name, sql)` runs a named SQL change once and records it in the table `RingMigrations`.

## Providers

The connection text selects the provider:

| Connection | Provider |
|---|---|
| `"Data Source=people.db"` | SQLite (bundled). `"Data Source=:memory:"` for an in-memory SQLite database |
| `"inmemory:name"` | the EF in-memory provider (no SQL, no migrations; same name = same database) |
| `"sqlserver:Server=.;Database=x;..."` | SQL Server — needs `Microsoft.EntityFrameworkCore.SqlServer.dll` next to the other assemblies |
| `"postgres:Host=...;..."` | PostgreSQL (Npgsql provider) |
| `"mysql:Server=...;..."` | MySQL (Pomelo provider) |

> [!WARNING] The SQL Server, PostgreSQL and MySQL providers are loaded **by name** from their NuGet packages and have **not been tested** here. SQLite and the in-memory provider are tested.

## The full EF API

Everything in EF Core is also wrapped as classes (`using { "Microsoft.EntityFrameworkCore" }`, `.ChangeTracking`, `.Infrastructure`, `.Metadata`, `.Metadata.Builders`, `.Storage`, `.Query`, `.Migrations`, `.Diagnostics`, `Microsoft.Data.Sqlite`; clashing names start with `Ef`). `oDb.context()` returns the real `DbContext`:

```ring
oContext = oDb.context()
? oContext.Database.ProviderName                 # Microsoft.EntityFrameworkCore.Sqlite
```

The complete list of methods is in the [Entity Framework reference](ef-reference.html). A complete program: `samples/UsingDotNet/applications/Contacts` — a contacts book with a console menu.
