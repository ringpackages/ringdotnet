Tutorial 10: Time, tasks and other programs

Measure how long something takes, wait for background work, read the environment, and run another program and read what it prints.

What you will learn#

  • Stopwatch to measure time,
  • tasks and Wait,
  • Environment: the computer and its variables,
  • Process: start another program,
  • the one important rule about threads.

The program#

docs/tutorials/t10_tasks_processes.ring
# Tutorial 10: time, tasks and other programs - Stopwatch, Task, Process, Environment
load "dotnet.ring"
using {
	"System"
	"System.Diagnostics"
	"System.Threading.Tasks"
	"System.Threading"
}

func main
	# Measuring time: Stopwatch
	oWatch = new Stopwatch()
	oWatch.Start()
	new Thread().Sleep(120)
	oWatch.Stop()
	? "Slept about 120 ms, measured at least 100: " + (oWatch.ElapsedMilliseconds >= 100)

	# Tasks run work in the background; Wait() waits for the end on the Ring thread
	oTask = new Task().Delay(100)
	? "Task finished at once?   : " + oTask.IsCompleted
	oTask.Wait(NULL)
	? "Task finished after Wait : " + oTask.IsCompleted

	# A task that has a result
	oResult = new Task().FromResult("done")
	? "Task result              : " + oResult.getProp("Result")

	# The environment
	oEnvironment = new Environment()
	? nl + "Machine name             : " + (len(oEnvironment.MachineName) > 0)
	? "Number of processors      : " + (oEnvironment.ProcessorCount >= 1)
	? "A variable (PATH) exists  : " + (len(oEnvironment.GetEnvironmentVariable("PATH")) > 0)
	? "Current folder is known   : " + (len(oEnvironment.CurrentDirectory) > 0)

	# Running another program and reading what it prints
	oInfo = new ProcessStartInfo() {
		FileName = "cmd"
		Arguments = "/c echo hello from another program"
		RedirectStandardOutput = True
		UseShellExecute = False
		CreateNoWindow = True
	}
	oProcess = new Process().Start([ :startInfo = oInfo ])
	cOutput = oProcess.StandardOutput.ReadToEnd()
	oProcess.WaitForExit(NULL)
	? nl + "The other program said: " + trim(cOutput)
	? "Its exit code            : " + oProcess.ExitCode

	# Important: Ring code runs on ONE thread. A task is good for waiting or for pure .NET work.
	# A callback that .NET runs on another thread can not call Ring (see 'Gotchas & limits').
Output
Slept about 120 ms, measured at least 100: 1
Task finished at once?   : 0
Task finished after Wait : 1
Task result              : done

Machine name             : 1
Number of processors      : 1
A variable (PATH) exists  : 1
Current folder is known   : 1

The other program said: hello from another program


Its exit code            : 0

How it works#

Stopwatch#

Start(), Stop(), then ElapsedMilliseconds (or Elapsed for a TimeSpan). Thread.Sleep(120) pauses the program for 120 ms. Measure the parts of a program that feel slow before you try to speed anything up.

Tasks#

A Task represents work that happens "in the background" or in the future. Task.Delay(100) is a task that completes after 100 ms. IsCompleted says whether it is done; Wait(NULL) blocks until it is. Task.FromResult("done") is a task that is already finished, with the result done, read with getProp("Result").

The rule: Ring runs on one thread#

Warning

.NET can do many things at once on many threads. Ring code runs on one thread only. A Ring callback that .NET tries to run from another thread is ignored. So use tasks for waiting and for pure .NET work (HTTP, files, hashing), and keep your Ring code on the Ring thread. Timers of Windows Forms (uiTimer) are safe: they tick on the Ring thread.

The environment#

Environment knows the computer: MachineName, ProcessorCount, CurrentDirectory, GetEnvironmentVariable("PATH"), UserName, OSVersion. The program prints only true for each, so that the output is the same on every computer.

Running another program#

ProcessStartInfo describes what to run: FileName, Arguments, and:

PropertyMeaning
RedirectStandardOutput = Trueyou read what the program prints
UseShellExecute = Falserun it directly (needed to redirect)
CreateNoWindow = Trueno console window

Process.Start([ :startInfo = oInfo ]) starts it; StandardOutput.ReadToEnd() reads all its output; WaitForExit(NULL) waits for the end; ExitCode is 0 when the program succeeded.

This is how a Ring program uses any command-line tool: git, ping, ffmpeg, dotnet.

What you learned#

  • time measuring and waiting,
  • tasks and their results,
  • the Ring-thread rule,
  • the environment and starting other programs.

Exercises#

  1. Measure how long it takes to compute 100000 square roots in a Ring loop.
  2. Run cmd /c dir and count the lines in its output.
  3. Print the three biggest environment variables by length (GetEnvironmentVariables()).
  4. Start notepad.exe with a Process, wait 3 seconds and close it with Kill().
