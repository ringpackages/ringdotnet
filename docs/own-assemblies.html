Appendix

Quick introduction to Ring

Your own assemblies

Wrap any .NET DLL — your own library or a NuGet package — with one command, and use its classes with the same simple syntax as the built-in ones.

Two ways to use an assembly#

WayWhen
Generic calls — dnLoad, dnType, dnNew, callMethoda quick call, nothing to generate
Generated classes — wrapassembly.ringthe simple oObj.Method() syntax, properties, events, enums, inheritance

Generic calls#

Ring
load "dotnet.ring"
dnLoad("path/to/MyLibrary.dll")                       # dependencies are found next to the dll

oCalc = dnNew("MyCompany.Tools.Calculator",[10])
oCalc.callMethod("Add",[5])
? oCalc.getProp("Total")                              # 15
? dnStatic("MyCompany.Tools.Calculator","Square",[7]) # 49

Generated classes#

Generate Ring classes for every public type of the DLL:

Shell
cd tools/dotnettools
ring wrapassembly.ring path/to/MyLibrary.dll ../../myclasses

This writes one loader per namespace and one file per class into myclasses/. Use them like any other wrapped namespace:

Ring
load "dotnet.ring"
dnLoad("path/to/MyLibrary.dll")
dnImportFrom("myclasses/","MyCompany.Tools")

oCalc = new Calculator()
oCalc.Add(10).Multiply(3)                             # fluent: methods that return a wrapped class return that class
? oCalc.Total                                         # 30
oCalc.Name = "mine"                                   # a property
? new Calculator().Square(7)                          # a static method
? oCalc.Describe([ :level = "High", :prefix = "Sum" ])                      # an enum as a string, an optional parameter
aDivide = oCalc.TryDivide(4)                          # out parameters come back in a list
? aDivide[2]

The generated classes support the same things as the built-in ones: real inheritance, properties as attributes, setXXXEvent() for events, enums as strings, overloads as one method with a hash list of parameters (Name([ :param = value ])), optional parameters and out / ref results.

The example in the package#

samples/UsingDotNet/tests/UserLib is a complete example — a small C# library, the generator run on it, and a test that uses it (samples/UsingDotNet/tests/test_userassembly.ring).

samples/UsingDotNet/tests/UserLib/Library.cs
samples/UsingDotNet/tests/UserLib/Library.cs
using System;
using System.Collections.Generic;

namespace MyCompany.Tools
{
	public enum Level { Low, Medium, High }

	public class Calculator
	{
		public double Total { get; private set; }
		public string Name { get; set; } = "calc";
		public event EventHandler Changed;

		public Calculator() { }
		public Calculator(double start) { Total = start; }

		public Calculator Add(double value) { Total += value; Changed?.Invoke(this, EventArgs.Empty); return this; }
		public Calculator Multiply(double value) { Total *= value; return this; }
		public static int Square(int x) { return x * x; }
		public static string EnumName(Enum value) { return value.GetType().Name + "." + value; }
		public string Describe(Level level, string prefix = "Total") { return prefix + "=" + Total + " (" + level + ")"; }
		public bool TryDivide(double by, out double result)
		{
			result = 0;
			if (by == 0) return false;
			result = Total / by;
			return true;
		}
		public List<string> Words(string text) { return new List<string>(text.Split(' ')); }
	}

	public class Counter : Calculator
	{
		public int Count { get; set; }
		public void Increment() { Count++; }
	}
	// An interface that inherits another one, and a class that is not public: Shapes.NewBox returns the interface IBox.
	// The wrapper must be IBox (the interface named after the class), with the members that IBox inherits from IShape.
	public interface IShape
	{
		string Name { get; set; }
		double Area();
	}

	public interface IBox : IShape
	{
		double Side { get; }
	}

	internal class Box : IShape, IBox
	{
		public string Name { get; set; } = "box";
		public double Side { get; private set; }
		public Box(double side) { Side = side; }
		public double Area() { return Side * Side; }
	}

	public static class Shapes
	{
		public static IBox NewBox(double side) { return new Box(side); }
	}
	// A class that is not public and implements a public interface explicitly (a row of Dapper is like this): the methods of the interface
	// are called on the object although the class has no public method of that name.
	public interface IGetter
	{
		string Fetch(string key);
		string Join(string first, string second);
		string Join(string only);
	}

	internal class Hidden : IGetter
	{
		string IGetter.Fetch(string key) { return key + "!"; }
		string IGetter.Join(string first, string second) { return first + "+" + second; }
		string IGetter.Join(string only) { return only; }
	}

	public static class Hiding
	{
		public static object NewGetter() { return new Hidden(); }
	}
	// A class with the name of a class of the library (System.Version): the generator gives it the prefix of its namespace, ToolsVersion,
	// so that both can be defined in one program.
	public class Version
	{
		public string Text { get { return "user version"; } }
	}
}
samples/UsingDotNet/tests/test_userassembly.ring
samples/UsingDotNet/tests/test_userassembly.ring
# Your own assemblies: tools/dotnettools/wrapassembly.ring generates the classes, dnImportFrom() loads them
load "dotnet.ring"

cHere = currentdir()
cLib = cHere + "/UserLib/bin/UserLib.dll"
if not fexists(cLib)
	system("dotnet build UserLib -c Release -o UserLib/bin -nologo -v q")
ok
cOut = cHere + "/UserLib/generated"
# the generator loads its files relative to the folder it runs from
chdir("../../../tools/dotnettools")
system(exefilename() + " wrapassembly.ring " + cLib + " " + cOut + " > nul")
chdir(cHere)
dnAssert("generated loader exists",fexists(cOut + "/MyCompany.Tools.ring"),1)

dnLoad(cLib)
dnImportFrom(cOut + "/","MyCompany.Tools")

oCalc = new Calculator()
oCalc.Add(10).Multiply(3)
dnAssert("fluent calls return the class",oCalc.Total,30)
dnAssert("property read/write",oCalc.Name,"calc")
oCalc.Name = "mine"
dnAssert("property write",oCalc.Name,"mine")
dnAssert("constructor with parameters",new Calculator().New_([ :start = 5 ]).Total,5)
dnAssert("static method",new Calculator().Square(7),49)
dnAssert("enum as string and optional parameter",oCalc.Describe([ :level = "High", :prefix = "Sum" ]),"Sum=30 (High)")
aDivide = oCalc.TryDivide(4)
dnAssert("out parameter ok",aDivide[1],1)
dnAssert("out parameter value",aDivide[2],7.5)
dnAssert("out parameter fails",oCalc.TryDivide(0)[1],0)
dnAssert("returns generic list",len(oCalc.Words("a b c").toList()),3)

nEvents = 0
oCalc.setChangedEvent("nEvents++")
oCalc.Add(1)
dnAssert("user event",nEvents,1)

# a class of the assembly with the name of a class of the library gets the prefix of its namespace, and both work in one program
dnAssert("a class named like a class of the library is renamed",new ToolsVersion().Text,"user version")
dnAssert("the class of the library has its own name",new Version("1.2.3").Major,1)

# methods that a non-public class implements explicitly are found through its public interfaces
oGetter = new Hiding().NewGetter()
dnAssert("a method of an explicit interface implementation",oGetter.Fetch("key"),"key!")
dnAssert("the same with named parameters",oGetter.Join([ :first = "a", :second = "b" ]),"a+b")

# a parameter of the type System.Enum does not say which enum it is: the text gives the full name of the member
dnAssert("a System.Enum parameter takes the full name of an enum member",new Calculator().EnumName("MyCompany.Tools.Level.High"),"Level.High")

# a class that is not public comes back as the interface named after it (IBox), and an interface has the members of the interfaces it inherits
oBox = new Shapes().NewBox(3)
dnAssert("a non-public class is wrapped as the interface named after it",classname(oBox),"ibox")
dnAssert("a member of the interface itself",oBox.Side,3)
dnAssert("a method inherited from another interface",oBox.Area(),9)
dnAssert("a property inherited from another interface",oBox.Name,"box")
oBox.Name = "big"
dnAssert("an inherited property can be set",oBox.Name,"big")

oCounter = new Counter()
oCounter.Increment()
oCounter.Increment()
oCounter.Add(2)
dnAssert("derived class property",oCounter.Count,2)
dnAssert("inherited method",oCounter.Total,2)
dnAssert("objects come back as the derived class",classname(oCalc.Add(0)),"calculator")

nFail = dnTestSummary()

NuGet packages#

A NuGet package is a set of DLL files. Let the .NET SDK collect them: a project file with a PackageReference and dotnet publish -o libs copy the package and the DLLs it depends on into one folder. Then wrap and load as above:

Shell
ring wrapassembly.ring libs/Newtonsoft.Json.dll ../../json
Ring
dnLoad("libs/Newtonsoft.Json.dll")
dnImportFrom("json/","Newtonsoft.Json.Linq")      # a namespace that needs another namespace of the same DLL loads it from the same folder
dnImportFrom("json/","Newtonsoft.Json")

The tutorial A NuGet package walks through this with a real package.

Entity Framework Core is wrapped the same way — that is how its classes were generated.

Which namespaces to wrap#

wrapassembly.ring <dll> <folder> [namespace ...] wraps only the namespaces you list. Without names, every namespace of the assembly is wrapped.

Rules#

  • Generated loaders use the names of the .NET classes. When a class name is also a name Ring or another namespace already uses, the generator can add a prefix — see Class generator.
  • Keep the DLL and its dependencies in one folder: assemblies are resolved next to the DLL you load.
  • The runtime mode matters: a DLL that needs Windows Forms requires the desktop mode first (a using block that names System.Windows.Forms, or dnUseDesktop()).
